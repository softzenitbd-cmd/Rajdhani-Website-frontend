# Permissions API Requirements & Documentation

## Overview
The frontend has been updated to support highly granular permissions for every single module and screen in the system. The frontend now manages permissions as a nested JSON object where each key represents a specific screen or module, and the value is an object representing boolean flags for `view`, `create`, `edit`, and `delete`.

---

## 1. Expected Data Structure (JSON)
The backend must support storing and returning a `permissions` JSON object in this exact format.

```json
{
  "dashboard": { "view": true, "create": false, "edit": false, "delete": false },
  
  "crm": { "view": true, "create": true, "edit": true, "delete": false },
  "crm_client_add": { "view": true, "create": true, "edit": false, "delete": false },
  "crm_client_list": { "view": true, "create": false, "edit": true, "delete": false },
  
  "account": { "view": true, "create": false, "edit": false, "delete": false },
  "acc_receive_add": { "view": true, "create": true, "edit": false, "delete": false },
  
  // ... and so on for all screens
}
```

*Note: In the frontend, the UI maps these flat keys into a nested visual structure.*

---

## 2. API Endpoints

### 2.1 Users / Admins Permissions
**Endpoint:** `PATCH /api/auth/users/{id}/permissions/`
**Payload:**
```json
{
  "custom_permissions": {
    "dashboard": { "view": true, "create": false, "edit": false, "delete": false },
    "crm_client_add": { "view": true, "create": true, "edit": false, "delete": false }
    // ... all other permissions
  }
}
```
**Response:**
The backend should successfully update the user's custom permissions and return `200 OK`. When fetching user details, `custom_permissions` must return this exact JSON structure so the UI can populate the checkboxes.

### 2.2 Staff Permissions (If managed separately)
**Endpoint:** `PATCH /api/staff/{id}/permissions/` *(or equivalent staff endpoint)*
**Payload:**
```json
{
  "permissions": {
    "dashboard": { "view": true, "create": false, "edit": false, "delete": false }
    // ... all other permissions
  }
}
```
*Note: Currently, the frontend `StaffPermission.jsx` mocks this save. Once the backend endpoint is ready, the frontend will be updated to hit the correct URL.*
